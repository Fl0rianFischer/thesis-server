# morning-briefing

A daily pre-market briefing, generated by Claude Code running headless on a
server and emailed before you wake up.

Covers macro, news per holding, upcoming earnings, and reviews of earnings that
just landed. It reads its own past briefings so it doesn't repeat itself.

No database, no backend, no API bill — it runs on a Claude subscription via a
long-lived OAuth token.

## How it works

```
cron (05:30)  →  run.sh  →  claude -p  →  archive/YYYY-MM-DD.md  →  Resend  →  inbox
```

`prompt.md` is the system prompt. `watchlist.md` is what it filters news
against. `archive/` is the memory: past briefings it reads before writing a new
one.

## Setup

### 1. Fill in your watchlist

Edit `watchlist.md`. The thesis line under each holding is what decides whether
a story makes the briefing — specific theses produce a signal-dense briefing,
vague ones produce noise. The "Not interesting" section at the bottom matters
just as much.

### 2. Try it locally first

Before touching the server, run it by hand a few mornings and tune `prompt.md`.
This is where the quality actually comes from.

```bash
./run.sh
```

Without `RESEND_API_KEY` set it writes `archive/<date>.md` and stops, which is
what you want while iterating.

### 3. Generate a subscription token

On a machine with a browser (your laptop, not the server):

```bash
claude setup-token
```

It prints a long-lived OAuth token and does **not** save it. Copy it now.

### 4. Deploy

```bash
rsync -av --exclude .git --exclude .env ./ root@YOUR_BOX:/opt/briefing/
```

On the box: install Claude Code, copy `.env.example` to `.env`, fill it in, and
confirm auth works.

```bash
claude auth status --text
```

Set the box timezone so `date +%F` and the cron hour mean what you think:

```bash
timedatectl set-timezone Europe/Berlin
```

### 5. Schedule it

```bash
crontab -e
```

```
30 5 * * 1-5 . /opt/briefing/.env && /opt/briefing/run.sh >> /opt/briefing/logs/cron.log 2>&1
```

## Design notes

**The agent has no shell.** `--allowedTools` grants `WebSearch,WebFetch,Read,Write,Glob`
and deliberately omits `Bash`. This agent reads untrusted web content every
morning, so email delivery lives in `run.sh` instead — a prompt injection in a
news article has no shell to reach for.

**`--bare` is deliberately not used.** The Claude Code docs recommend it for
scripts, but it ignores OAuth credentials and falls back to `ANTHROPIC_API_KEY`
billing, and it strips `WebSearch`/`WebFetch` from the toolset. Both are fatal
here. The cost is that Claude Code auto-discovers `CLAUDE.md`, hooks, and MCP
servers in the working directory and `~/.claude` — keep the box clean.

**Failure is detected by the artifact, not the exit code.** Claude Code reports
in-run failures, including expired auth, as the result on stdout. `run.sh`
checks that `archive/<date>.md` exists and is non-empty; that's the real signal.

## Troubleshooting

**Nothing arrives, and it worked by hand.** Almost always cron's empty
environment. Check `PATH` in `.env` points at wherever `which claude` reports on
the box, and that the crontab line sources `.env` before running.

**It stops working after weeks of running.** The OAuth token expired. Re-run
`claude setup-token` and update `.env` before debugging anything else.

**It's eating your usage limits.** A 30–40 turn research run is a real chunk of
a Pro budget and competes with your own Claude Code usage. Lower
`BRIEFING_MAX_TURNS`, drop `BRIEFING_EFFORT` to `low`, or run three mornings a
week (`30 5 * * 1,3,5`). If it's still tight, the ladder is Max, or API billing
with `ANTHROPIC_API_KEY` — around $22/month on `sonnet` with these caps.

**The briefing is padded or repetitive.** Tighten the thesis lines in
`watchlist.md` and extend the "Not interesting" list. That fixes it far more
reliably than editing `prompt.md`.

## Cost

On a Claude Pro subscription: **$0 marginal** — it draws on usage limits rather
than per-token billing. `logs/<date>.json` records `total_cost_usd` per run, so
you can see what an equivalent API run would have cost if you ever switch.
