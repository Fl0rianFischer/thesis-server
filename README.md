# morning-briefing

A daily pre-market briefing, generated by Claude Code running headless on a
server and emailed before you wake up.

Covers macro, news per holding, upcoming earnings, and reviews of earnings that
just landed. It reads its own past briefings so it doesn't repeat itself.

No database, no backend, no API bill — it runs on a Claude subscription via a
long-lived OAuth token.

## How it works

```
push to main  →  GitHub Actions  →  GHCR image  →  ssh deploy  →  /opt/briefing

host cron (05:30)  →  docker compose run --rm briefing
                         →  claude -p
                         →  data/archive/YYYY-MM-DD.md
                         →  Resend  →  inbox
```

`prompt.md` is the system prompt. `watchlist.md` is what it filters news
against. Both are baked into the image, so changing your holdings is a commit
and a deploy — versioned and revertible like anything else.

`data/archive/` on the box is the memory: past briefings the agent reads before
writing a new one. It's a bind-mounted volume, so it survives redeploys. Losing
it means every morning starts cold.

There is no long-running service. The container is ephemeral — cron fires it,
it writes a briefing, it exits.

## Setup

### 1. Fill in your watchlist

Edit `watchlist.md`. The thesis line under each holding is what decides whether
a story makes the briefing — specific theses produce a signal-dense briefing,
vague ones produce noise. The "Not interesting" section at the bottom matters
just as much.

### 2. Try it locally first

See [Testing locally](#testing-locally) below. Do this before touching the
server — the prompt is where the quality comes from, and tuning it through a
cron log is miserable.

### 3. Generate a subscription token

On a machine with a browser (your laptop, not the server):

```bash
claude setup-token
```

It prints a long-lived OAuth token and does **not** save it. Copy it into the
`CLAUDE_CODE_OAUTH_TOKEN` repository secret.

### 4. Configure GitHub

**Secrets** (Settings → Secrets and variables → Actions):

| Secret | What |
|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | From `claude setup-token` |
| `RESEND_API_KEY` | Resend API key |
| `SSH_HOST` / `SSH_USER` / `SSH_PRIVATE_KEY` | The box (reused from the old deploy) |

**Variables:**

| Variable | Example |
|---|---|
| `TZ` | `Europe/Berlin` |
| `MAIL_FROM` | `briefing@yourdomain.example` |
| `MAIL_TO` | `you@example.com` |
| `BRIEFING_MODEL` | `sonnet` |
| `BRIEFING_EFFORT` | `medium` |
| `BRIEFING_MAX_TURNS` | `40` |
| `BRIEFING_CRON` | `30 5 * * 1-5` |

### 5. Prepare the box, once

```bash
sudo git clone https://github.com/fl0rianfischer/morning-briefing.git /opt/briefing
```

The checkout only supplies `docker-compose.yml` — everything else ships in the
image. Confirm Docker can pull from GHCR (`docker login ghcr.io` with a PAT
carrying `read:packages`, if the package is private).

### 6. Push to main

The workflow builds the image, writes `/opt/briefing/.env`, pulls, and installs
the cron entry. The schedule comes from `BRIEFING_CRON` and is reinstalled on
every deploy, so it can't drift on the box.

Trigger a run by hand to check the whole path end to end — this one does send
the email:

```bash
cd /opt/briefing && docker compose --profile cron run --rm briefing
```

## Testing locally

Four rungs, cheapest first. Don't skip to the bottom — each one isolates a
different failure.

### 1. The prompt, no Docker

Fastest loop, and the only one that matters for output quality. Uses your
existing interactive Claude Code login, so no token needed.

```bash
set -a; . ./.env; set +a
```

```bash
./run.sh
```

With `RESEND_API_KEY` empty it writes `archive/<date>.md` and stops. Read it,
edit `watchlist.md` and `prompt.md`, delete the file, run again. Expect several
rounds — the thesis lines and the "Not interesting" list do most of the work.

To iterate without waiting for a full research run, cap it:

```bash
BRIEFING_MAX_TURNS=8 BRIEFING_EFFORT=low ./run.sh
```

### 2. The image builds and Claude runs in it

This is where the genuinely unknown parts are: whether Claude Code installs
cleanly, runs as a non-root user, and finds a writable `HOME` in the container.

Needs a real `CLAUDE_CODE_OAUTH_TOKEN` in `.env` — the container can't reach
your host's login. Generate one with `claude setup-token`.

```bash
docker build -t ghcr.io/fl0rianfischer/morning-briefing:local .
```

Then a five-second smoke test that skips the briefing entirely and just proves
the image and auth work:

```bash
docker compose --profile cron run --rm --entrypoint claude briefing -p "Reply with OK and nothing else." --model haiku
```

If that prints `OK`, the image, the token, and network egress are all fine. If
it doesn't, nothing below will work — fix it here.

### 3. A real run through Compose

Same command cron will use on the box:

```bash
docker compose --profile cron run --rm briefing
```

Check `data/archive/` for the briefing and `data/logs/<date>.json` for the run
metadata. This also verifies the volume mounts — if the briefing lands inside
the container instead of `data/archive/`, the mount is wrong and every morning
would start with no memory.

### 4. The email path

Test it on its own rather than through a full run:

```bash
curl -fsS https://api.resend.com/emails -H "Authorization: Bearer $RESEND_API_KEY" -H "Content-Type: application/json" -d '{"from":"briefing@yourdomain.example","to":["you@example.com"],"subject":"test","text":"hello"}'
```

Most failures here are Resend domain verification, not the script.

### Testing the deploy itself

The workflow only runs on push to `main`, so use a scratch branch and
`workflow_dispatch` from the Actions tab to trigger it without merging.

The one thing you can't rehearse locally is cron on the box. After the first
deploy, confirm the entry landed:

```bash
crontab -l | grep morning-briefing
```

## Design notes

**The agent has no shell.** `--allowedTools` grants `WebSearch,WebFetch,Read,Write,Glob`
and deliberately omits `Bash`. This agent reads untrusted web content every
morning, so email delivery lives in `run.sh` instead — a prompt injection in a
news article has no shell to reach for.

**`--bare` is deliberately not used.** The Claude Code docs recommend it for
scripts, but it ignores OAuth credentials and falls back to `ANTHROPIC_API_KEY`
billing, and it strips `WebSearch`/`WebFetch` from the toolset. Both are fatal
here. The cost is that Claude Code auto-discovers `CLAUDE.md`, hooks, and MCP
servers in the working directory and `~/.claude` — keep the box clean.

**Failure is detected by the artifact, not the exit code.** Claude Code reports
in-run failures, including expired auth, as the result on stdout. `run.sh`
checks that `archive/<date>.md` exists and is non-empty; that's the real signal.

**Ephemeral container, not a scheduled service.** Host cron runs
`docker compose run --rm`. No cron daemon in the image, no supervisor, nothing
to keep alive — and the thing cron runs is exactly the thing you can run by
hand. `profiles: [cron]` keeps a stray `docker compose up -d` from firing a
briefing as a side effect of poking at the box.

**Compose supplies the environment.** The classic cron failure — empty `PATH`,
missing tokens — doesn't apply, because `env_file: [.env]` is read by Compose
rather than inherited from cron. The installed entry only needs an absolute path
to `docker`.

## Troubleshooting

**Nothing arrives.** Check `data/logs/cron.log`, then `data/logs/<date>.json`
for the run itself. On failure `run.sh` logs a `FAILED` line plus the first 500
characters of Claude's result, which is usually the whole answer.

**It stops working after weeks of running.** The OAuth token expired. Re-run
`claude setup-token`, update the `CLAUDE_CODE_OAUTH_TOKEN` secret, and redeploy
— check this before debugging anything else.

**It's eating your usage limits.** A 30–40 turn research run is a real chunk of
a Pro budget and competes with your own Claude Code usage. Lower
`BRIEFING_MAX_TURNS`, drop `BRIEFING_EFFORT` to `low`, or run three mornings a
week (`BRIEFING_CRON=30 5 * * 1,3,5`). If it's still tight, the ladder is Max,
or API billing with `ANTHROPIC_API_KEY` — around $22/month on `sonnet` with
these caps.

**The briefing is padded or repetitive.** Tighten the thesis lines in
`watchlist.md` and extend the "Not interesting" list. That fixes it far more
reliably than editing `prompt.md`.

**`docker compose pull` fails on the box.** The GHCR package is private by
default and is a *different* package from the old `thesis-server` one. Either
make it public, or `docker login ghcr.io` with a PAT carrying `read:packages`.

## Cost

On a Claude Pro subscription: **$0 marginal** — it draws on usage limits rather
than per-token billing. `data/logs/<date>.json` records `total_cost_usd` per
run, so you can see what an equivalent API run would have cost if you ever
switch to `ANTHROPIC_API_KEY`.
